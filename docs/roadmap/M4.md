# M4 — Second Scenario and Evidence-led Reuse

> Status: pending

## Goal and method

Use M3 findings to choose one second scenario or independent host. State the
reuse hypothesis, observable behavior IDs, baseline, and limits before building.
A new persona alone is insufficient. Deployment watch is an optional candidate
for background lifecycle reuse; it cannot establish realtime generality.

Map both uses to actual code and provider-native capabilities. Preserve live
responsiveness, coordinated output, and one authority for grants/state/retries.
Extract only the smallest independently useful unit. If none is justified,
keep internal boundaries and independently reproduce the reference app instead.
One product can contain distinct live and background execution paths.

An extracted Python surface uses `typing.Protocol`, full types, and explicit
ownership of lifecycle, grants, playback, retries, and persistence. Document the
serialization, cancellation, partial/unknown outcomes, and version compatibility
actually exercised. Generic routing uses IDs; applications interpret meaning.
Do not force a snapshot decision API, sensor registry, or vendor platform.

Recheck applicable scenarios and representative live experience after adaptation.
The handoff identifies what can be released and what remains unproven.

## Exit criteria

- [ ] **M4-E7** (document) The second scenario and its hypothesis are justified by M3
      evidence, with explicit behavior IDs and limits of the comparison.
- [ ] **M4-E8** (integration, document) The second use is exercised and compared with a
      simple applicable baseline; reused mechanisms and unsupported generalizations are
      recorded.
- [ ] **M4-E9** (document) Each proposed reusable contract maps to an observed integration
      need; the extraction decision, including no extraction if appropriate, and
      architectural strain are recorded.
- [ ] **M4-E10** (replay, owner) Applicable scenarios still pass and the owner checks
      representative live co-presence/continuity for regressions after adaptation.
- [ ] **M4-E11** (integration) An independent setup exercises any extracted component, or
      reproduces the reference app if no component is justified, with clear lifecycle
      ownership and no competing schedulers.
- [ ] **M4-E12** (document) M4 handoff identifies the reproducible experience and any
      evidenced component contracts ready for release, with unresolved limits and no
      unsupported generality claims.

# M3 — Extract the Decision Core

> Status: pending
> Prerequisite reading: [Roadmap.md](../../Roadmap.md), [M1.md](M1.md), [M2.md](M2.md)

## Goal

Turn the M2 prototype into two cleanly separated layers, without adding
features:

- **Decision core**: pure, embeddable, single-call — the actual product.
- **Run shell**: persistence, scheduling, execution — a replaceable
  reference implementation.

## Target shape

```python
class DecisionEngine(Protocol):
    async def evaluate(self, context: ContextSnapshot) -> Decision: ...

class Executor(Protocol):
    async def execute(self, action: Action, *,
                      idempotency_key: str) -> Outcome: ...
```

- `Decision` distinguishes at least: `Execute(action)`,
  `Wait(until, wake_on)`, `Complete(reason)`. Notification is an ordinary
  action with its own rate limits. Actions needing extra authorization
  produce an explicit waiting state handled by the host.
- Every decision records: brief rationale, referenced observations,
  estimated budget consumption, and the state version it applies to.
  Auditable records, not full model reasoning.
- `evaluate()` may call a model but **must not** send messages, mutate
  external systems, or schedule real timers. It returns; the shell acts.

## State model

Three kinds of data, kept apart:

1. **Run state**: active concerns, next wake-ups, budgets, in-flight actions.
2. **Facts and execution records**: what was observed, decided, and what
   actually happened.
3. **Long-term preferences and knowledge**: user interests, notification
   habits. Minimal and structured for now.

SQLite carries (1) and (2). "Have I sent this notification" and "is this
task done" are exact queries — never semantic retrieval.

## Run-shell reliability rules (single process)

- One concern is processed sequentially; before executing, re-check that
  the decision is not stale against newer state.
- Deduplicate and coalesce high-frequency events; never one model call per
  raw message.
- Persist waits and wake times; restore them on restart (S9).
- Cap steps, time, and cost per investigation to stop self-triggered
  cascades.
- Distinguish "definitely failed" from "outcome unknown"; unknown outcomes
  are verified or handed to the host — never blindly retried.

## Interface rules

- All pluggable surfaces are `typing.Protocol`; users must not be forced to
  import base classes to satisfy an interface.
- Event payloads must be serializable (generics or codec hooks allowed);
  the framework still never interprets them.
- Ship a few convenience implementations (queue source, callback effector)
  to lower adoption cost. Convenience is not business binding.

## Exit criteria

- [ ] The M2 scenario pack passes against the extracted core + shell with
      no behavior regressions.
- [ ] A second, toy host (plain script with its own loop) drives the core
      through `evaluate()` alone — proving embedded mode works.
- [ ] Public surface documented; everything not exercised by a scenario
      stays internal.

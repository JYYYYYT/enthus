# M3 — Continuity and Sustained Experience

> Status: pending
> Behavior: [S33-S35](M1.md#scenarios), after M2 acceptance.

## Goal and trial

Test whether the companion remains worth choosing across repeated sessions.
Implement accurate recall of shared experiences (S33), correction (S35), and
only justified background follow-up (S34).

Before the trial, record dates, activities, participants, input grants, model/
prompt/config versions, memory scope, budgets, rubric, and baseline. A week is
an initial proposal; agree duration and opportunities before evaluation. Limited
opportunities mean limited evidence, not a reason to increase interruptions.

Review substance, grounding, shared attention, timing, interruption, continuity,
and burden. Record welcome/neutral/unwanted judgements with reasons, sampled
silence and misses, and whether the owner chooses to reopen sessions. Message
counts, reply rate, and session length alone do not prove value. Memories retain
provenance; current corrections win. Loading memory never enables sensors.

## Background follow-up, only if useful

Record the actual need first; leaving A disabled is valid. If enabled, use one
source and a bounded grant with identity, expiry, cancellation, resource limits,
and separate off-session delivery permission. Follow [applicable S11-S25 behavior](../history/M1-2026-09-17.md).
Test S34 without blocking live interaction or seizing playback, including empty/
error results, cancelled/late results, duplicates, exhaustion, and silent endings.
If disabled, verify ungranted background work stays off and mark fusion untested.

## Compare and refine

Retain M2's direct-model baseline; compare continuity with/without added memory
selection under comparable context and opportunities. Add a scheduled-follow-up
baseline only for enabled A behavior. Report latency, cost, omissions, burden,
reopening reasons, and cases with no Enthus advantage. Small owner trials are
diagnostic, not market evidence.

Refine prompts, timing, observation selection, and bounded memory from failures.
Version material changes and separate before/after results. Memory synthesis
needs source references and atomic updates; semantic retrieval needs a concrete
recall failure and comparison with simpler fixes. No unlimited media retention,
general memory framework, vendor platform, or API extraction is required.

- [ ] **M3-E9** (document, replay) The need for A is evaluated; if enabled, replays cover

      are explicit.
- [ ] **M3-E10** (replay) Failures observed during use have regression coverage; M2's
      presence/control scenarios and any enabled background behavior remain correct.
- [ ] **M3-E11** (document) Baseline comparison includes continuity, burden, latency,
      resource use, reopening behavior, and cases with no Enthus advantage, with trial
      limitations.
- [ ] **M3-E12** (owner, document) The owner judges the experience worth continuing; an M3
      handoff identifies evidenced reuse needs and any remaining limits without assuming a
      framework must be extracted.

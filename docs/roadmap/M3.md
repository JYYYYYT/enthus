# M3 — Experience Validation and Refinement

> Status: pending
> Prerequisite reading: [Roadmap.md](../../Roadmap.md), [M1.md](M1.md), [M2.md](M2.md)

## Goal

Find out whether the proactive conversation MVP is worth living with beyond
its first demonstration. Improve content selection, timing, continuity, and
feedback handling based on observed failures. Do not extract a general
framework in this milestone.

## Trial protocol

Before starting, record the trial dates, allowed sources, model/prompt/config
versions, budgets, channel, and evaluation rubric. Start with a seven-day
owner trial as a proposed protocol; the owner may choose another duration
before the run. Insufficient opportunities mean insufficient evidence, not a
reason to increase message volume to satisfy a quota.

Use these review dimensions for every unsolicited intervention:

| Dimension | Review question |
|---|---|
| Substance | Did it add something specific worth considering or discussing? |
| Continuity | Did it use shared history accurately and relevantly? |
| Grounding | Are claims about findings, history, and user interests supported? |
| Timing | Was this a suitable moment and channel? |
| Burden | Did it repeat itself, pressure a reply, or create unwanted obligation? |

Record a short owner verdict (welcome / neutral / unwanted) and reason,
without treating these labels as calibrated probabilities. Review a sample of
withheld opportunities to find omissions; a system that never speaks is not
validated merely because it never annoys anyone. Keep direct user statements,
inferences, and nonresponse distinct in the records.

## Baseline and measurements

Compare with a simple scheduled check-in policy on comparable conversation
histories and information opportunities, using the same model, memory/source
access, and resource/notification limits where applicable. Its timing follows
a fixed schedule; it may still obey hard gates. Record unavoidable differences.
Counterfactual baseline messages can be reviewed offline to avoid doubling
live interruptions. This small owner study is diagnostic, not a population
claim or a statistically established advantage.

Report:

- Intervention judgements and representative reasons, including bad examples.
- Missed opportunities identified in sampled waits or ended explorations.
- Repeated/unsupported content and failures to honor explicit corrections.
- Actual model/tool costs, context size, and unnecessary investigation.
- Hard-gate and recovery failures; these require a fix and regression coverage.
- What the baseline did as well or better, and what the extra machinery bought.

Reply rate and message count are descriptive only. Do not optimize them as
standalone measures of companionship or value.

## Permitted refinement

Adjust prompts, bounded memory selection, topic updates, cadence, and simple
heuristics. Add semantic retrieval only after documenting a concrete recall
failure, the attempted simpler remedy, and a bounded evaluation of the change.
A new storage service is not assumed to be necessary.

Give preference corrections and cancellation immediate effect; background
memory processing must not delay them. If introducing memory synthesis,
retain source references and versioned updates, commit progress atomically,
and ensure retries cannot double-apply updates or revive removed information.

Version material changes during the trial and distinguish before/after
observations. Feed reproducible failures into S11–S25 scenario packs. Do not
require the user to answer unwanted messages to provide evaluation data.

## Exit criteria

- [ ] Trial protocol recorded and completed; duration and evidence limitations
      documented, with owner review of interventions and sampled withheld cases.
- [ ] Comparison with the scheduled baseline written, including tradeoffs,
      costs, and cases where the MVP provided no advantage.
- [ ] Explicit feedback demonstrably changes later behavior (S13/S21), while
      nonresponse does not trigger reminders or an unsupported preference claim.
- [ ] Observed reliability failures fixed and S11–S25 regression pack passes.
- [ ] Owner judges the experience worth continuing, with unresolved weaknesses
      recorded. Technical correctness alone cannot satisfy this criterion.
- [ ] A `NOTES.md` handoff identifies evidenced extension needs for M4; no
      public API is frozen merely because the trial has ended.

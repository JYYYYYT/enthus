# M5 — API Stabilization and Open-Source Release

> Status: pending
> Prerequisite reading: [Roadmap.md](../../Roadmap.md), [M3.md](M3.md), [M4.md](M4.md)

## Goal

Ship Enthus as a citable, low-level open-source module — only the parts
that both scenario families actually exercised.

## Scope rules

- The public API is the intersection of what M3 and M4 needed, no more.
  Anything used by one family stays experimental; anything used by neither
  is deleted.
- Semantic versioning from the first tag. Breaking changes require a major
  bump and a changelog entry explaining the scenario that forced them.
- Zero required third-party dependencies beyond the Python standard
  library for the decision core; model SDKs and storage backends are
  optional extras.

## Deliverables

- [ ] Package published (PyPI), name resolved.
- [ ] README: the vision in two paragraphs, the concern-centered loop in
      one diagram, a 20-line embedded-mode example, a standalone-mode
      example. The biology metaphor (curiosity, attention) lives here as
      philosophy — never in API names.
- [ ] API reference generated from docstrings.
- [ ] Behavior-spec traceability: each public interface annotated with the
      M1 scenarios that justify it.
- [ ] Integration example: embedded inside a LangGraph workflow, using the
      host's persistence and interrupts.
- [ ] Contribution guide and a honest "non-goals" section (not an agent
      framework, not a memory system, not a persona engine).

## Release criteria

- [ ] A consumer who has never read this roadmap can embed the decision
      core in under an hour, using only the README and API reference.
- [ ] Both scenario packs run as CI-replayable tests.
- [ ] The known deep-water areas are documented as such: candidate-action
      comparison is currently heuristic, not calibrated decision theory;
      concern auto-origination is budget-capped but not yet principled.

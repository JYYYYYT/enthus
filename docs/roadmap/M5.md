# M5 — API Stabilization and Open-Source Release

> Status: pending
> Prerequisite reading: [Roadmap.md](../../Roadmap.md), [M3.md](M3.md), [M4.md](M4.md)

## Goal

Ship the reusable decision layer justified by the conversation experience and
the work scenario, with a reference conversational application and a replaceable
runtime. The release must communicate both the experiential evidence and the
technical limits.

## Scope rules

- Stabilize contracts exercised across the two families or required by a
  demonstrated host integration. Keep scenario-specific behavior in adapters
  and examples; unexercised abstractions do not become public API.
- Use semantic versioning and document the compatibility policy, including
  how breaking changes are signaled during 0.x development and after 1.0.
- Keep the decision core free of required third-party dependencies beyond the
  Python standard library. Model SDKs, source/channel connectors, and optional
  storage/retrieval backends are extras with documented dependency reasons.
- The core is persona-neutral and can use host-owned memory. The reference
  companion includes enough memory and expression configuration to reproduce
  the validated experience; it is not a general memory or roleplay platform.

## Deliverables

- [ ] **M5-E1** (release) Package published to PyPI with a resolved name, typed public API, and
      `py.typed`.
- [ ] **M5-E2** (document) README explains the conversation-first evidence and long-term module
      positioning, with a small embedded example and a standalone chat example.
- [ ] **M5-E3** (document) API reference, configuration guide, and recovery/serialization contracts.
- [ ] **M5-E4** (document) Traceability from public interfaces to M1 scenarios and M4 integration needs.
- [ ] **M5-E5** (integration) Integration example using an existing agent workflow's lifecycle and
      persistence, without forcing it to run a competing Enthus scheduler.
- [ ] **M5-E6** (document) Contribution guide, license, changelog, and explicit scope boundaries.
- [ ] **M5-E7** (document) Summarized M3 owner-trial findings and M4 baseline comparison, with
      limitations and without exposing private conversation history.

## Release criteria

- [ ] **M5-E8** (integration) A new consumer can embed the core using only the public documentation;
      demonstrate the target of a basic integration in under an hour.
- [ ] **M5-E9** (replay) Both scenario families run as CI-replayable tests with versioned fixtures;
      live evaluation is documented separately and is not presented as deterministic.
- [ ] **M5-E10** (integration) Embedded and standalone usage agree on decision semantics and identify
      one owner for state, scheduling, and retries in each mode.
- [ ] **M5-E11** (document) Known limits are explicit: initiative selection is heuristic, inferred
      preferences are fallible, small owner trials do not establish broad appeal,
      and external exactly-once effects depend on downstream capabilities.
- [ ] **M5-E12** (document) Remaining automatic-origination and retrieval experiments are labeled
      experimental rather than implied to be solved by a generic interface.

## Scenarios

### S26 — A reply ends while the shared environment continues

- **Situation:** In an explicitly granted session, a reply finishes. Without a
  new user message, upload, or per-frame command, the shared visual scene changes.
- **Expected:** New observations continue arriving with timestamps/provenance.
  Later interaction can use that change. The host distinguishes output completion
  from session end and receptive silence from stopped/degraded sensing. Test an
  actual change that was absent from the prompt; prerecorded input is labeled.
- **Validates:** CP1/CP2 and continued perception rather than a persistent process.

### S27 — Participation prompted by a shared event

- **Situation:** A relevant change occurs in the shared activity, connected to
  what the user and companion were attending to. No fresh question is asked.
- **Expected:** The companion can offer a grounded, context-specific contribution
  at a suitable moment. It must also withhold a comparable irrelevant or poorly
  supported candidate. It need not describe every change or invent a work task.
  A meaningful new observation, not a timer alone, explains the example.
- **Validates:** CP4's selective initiative within actual shared experience.

### S28 — The user interrupts output

- **Situation:** The companion is generating/playing speech when the user starts
  an interruption or explicitly stops speech.
- **Expected:** Continue receiving input; stop audible output within the declared
  target, clear pending playback, and cancel or invalidate the old generation.
  Late chunks cannot restart it. Subsequent participation responds to the new
  context. Record the played portion and any uncertainty, not the full draft as
  heard. No requirement to wait for a slow reasoning/research call to finish.
- **Validates:** CP3, measurable interruption, and truthful partial-output memory.

### S29 — A candidate becomes stale before or during delivery

- **Situation:** A relevant scene/topic/scope change makes a pending contribution
  obsolete while generation, a tool call, or queued playback is still running.
- **Expected:** Reassess affected content against fresh context; discard pending
  stale output and stop any obsolete remainder as appropriate. Preserve what was
  already played without pretending to undo it. A new frame alone need not cancel
  all speech; invalidation follows relevant change, with traceable versions.
- **Validates:** Freshness across asynchronous paths and bounded output queues.

### S30 — Quiet participation without abandoning perception

- **Situation:** The user is absorbed in the activity, background speech is not
  addressed to the companion, or an observation has little to add.
- **Expected:** Withhold unnecessary commentary and remain receptive. A later
  relevant event or direct address can still receive an appropriate response.
  Do not demand a reply, infer dislike from silence, or claim background speech
  establishes a user instruction. Review both unwanted speech and missed cases.
- **Validates:** CP2/CP4 and selective attention rather than constant narration.

### S31 — Distinct controls for speech, sensing, and background activity

- **Situation:** The user changes what participation or observation is allowed.
- **Expected:** Provide distinguishable controls with visible scope/effect:
  stop current speech cancels its remaining output; mute unsolicited speech
  leaves direct replies possible; stop a selected sensor revokes that input;
  end the session stops its sensors/playback and invalidates session output;
  cancel a background follow-up revokes that activity and its late outputs.
  An explicit stop-all control ends the session and all enabled background
  activity. No operation silently re-enables a previously revoked permission.
  Persistent grants and current state resolve exactly which activity may remain.
- **Validates:** CP5 and comprehensible control, without conflating playback mute
  with microphone mute or assuming a quiet request grants ongoing sensing.

S15's historical permission to continue bounded source research during delivery
mute does not grant live microphone/camera capture. A session ending preserves
history; deletion/forgetting is a separate operation, never implied by mute.
Natural-language control claims require actual effect evidence; deterministic
controls must remain available while model interpretation is uncertain.

### S32 — Perception, connection, or resources become unavailable

- **Situation:** A sensor or model stream disconnects, a session limit expires,
  or the host restarts. Pending input/output or a reconnect may still arrive.
- **Expected:** Expose stopped/degraded state and discard invalid queued work.
  Do not claim to keep seeing/hearing unavailable input. Reconnect requires a
  still-valid grant and fresh context; explicit stop/expiry cannot be undone by
  retry. Host restart leaves capture off until explicitly started. Enforce
  duration/resource bounds without requiring a model-generated farewell.
- **Validates:** Honest bounded presence and recovery without phantom observation.

### S33 — A shared experience continues in another session

- **Situation:** The user explicitly starts a later session after a prior shared
  activity. Relevant history exists, including what was actually observed/said.
- **Expected:** Select accurate useful history with provenance, distinguish it
  from the current scene, and accept corrections. Do not automatically start
  sensors while loading memory, replay unfinished speech, or fabricate what
  happened between sessions. Compare with a baseline without added continuity.
- **Validates:** CP6 and cross-session continuity; first implemented in M3.

### S34 — A bounded follow-up rejoins live interaction

- **Situation:** An independently authorized background activity produces a
  result during a shared session, or after that session ends.
- **Expected:** Route by activity identity into shared context and reconsider
  relevance/timing; never block input or seize playback. Suppress cancelled,
  duplicate, unsupported, or obsolete results. After session end, off-session
  delivery still needs its own grant. Test no-value and cancelled-result cases;
  no background research is required if the trial shows no need for it.
- **Validates:** A/B continuity with separate execution and coordinated output.

### S35 — A correction changes current participation

- **Situation:** The user corrects a perceived detail, remembered fact, or desired
  participation style while incompatible output is being prepared.
- **Expected:** Preserve the user correction as current evidence, invalidate
  incompatible pending content, and demonstrate the change in later behavior.
  Distinguish an uncertain observation from a user-confirmed fact. Do not infer
  intention from pixels alone, or preferences from the companion's own messages.
- **Validates:** Grounding, revisable interpretation, and effective user feedback.

## State transitions

These are observable semantics, not required APIs or a model call per media chunk.

| ID | Trigger | Decision or host transition | Resulting state |
|---|---|---|---|
| S26 | Reply ends; new scene arrives | Retain granted session; ingest fresh observation | Output idle, perception active, context advances |
| S27 | Relevant shared event without question | Propose grounded participation or receptive wait | Current candidate delivered only if allowed |
| S28 | User interrupts playing speech | Host stops playback, clears queue, invalidates generation | Partial output recorded; new input remains available |
| S29 | Relevant context invalidates candidate | Reassess; cancel or discard affected remainder | Stale output cannot resume on late chunks |
| S30 | Irrelevant input or no useful contribution | Receptive silence | Inputs still accepted; no pressure or inferred dislike |
| S31 | User changes speech/sensor/session/background scope | Host applies the specific revocation | Unaffected valid grants remain; revoked work cannot revive |
| S32 | Disconnect, expiry, or restart | Host degrades/stops and reconciles | Honest status; no stale replay or implicit sensor restart |
| S33 | Explicit later session start | Select evidenced history plus fresh current observations | Accurate continuity without invented intervening events |
| S34 | Granted background outcome | Route by ID and re-evaluate relevance/output permission | Live path remains responsive; result shared, held, or discarded |
| S35 | User corrects perception/memory/style | Revise current evidence; invalidate incompatible candidate | Later participation reflects correction |
